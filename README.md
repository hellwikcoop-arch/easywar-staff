# EasyWAR Staff

Спільне сховище для синтетичних задач штабу: JE — командир, J5 — планування, J3 — виконання, C5.4 — рецензія логіки.

- [Шаблон наказу](templates/order.yaml) — копіювати у каталог нової задачі.
- [Результати T-0001](tasks/T-0001/) — прийняті версії, байти збережено.

- [Походження та перевірка перенесення](docs/migration.md).

## Робота через GitHub

1. J5 готує наказ у `tasks/T-XXXX/order.yaml` за шаблоном; J3 підтверджує прийняття.
2. J3 створює результати у гілці задачі й відкриває PR; донесення зберігаються у `reports/T-XXXX/`.
3. Перевірки, рецензія і приймання вказують конкретний commit або SHA-256 файлів за наказом.
4. Зміни файлів репозиторію проходять C3 за розділом 6 контракту; змістове приймання надає J5, ключові рішення — JE.
5. Стан та append-only `events.jsonl` веде ADM. До його реалізації діє ручний режим людиною за розділом 26. Агенти не створюють офіційний стан від імені ADM.

Репозиторій сам по собі не запускає агентів і не передає їм задачі автоматично. Доступ Claude до нього потрібно перевірити окремо. Автоматичний облік викликів і витрат ще не налаштовано.

Не змінювати прийняті `data.csv` і `filter_results.md` без нових перевірок та рецензії. Первинна інтеграція сховища потребує C3; вона не є повторним виконанням T-0001.

Перевірка байтів результатів із кореня репозиторію:

```sh
sha256sum -c tasks/T-0001/SHA256SUMS
```
