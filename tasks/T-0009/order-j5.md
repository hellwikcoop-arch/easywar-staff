# T-0009 — Автоматизація J4 Bridge, етап 1

**Ініціатор:** J5  
**Виконавець:** J3  
**Координатор:** ADM / J4  
**База:** `hellwikcoop-arch/easywar-staff`, `setup/staff-bootstrap`  
**Статус:** наказ J5 на підготовку й виконання в межах рівня A  
**Режим:** synthetic-only, stub, без платних API

## 1. Мета

Забезпечити автоматичне виконання дозволених операцій J4 Bridge без ручного запуску кожного кроку.

Автоматизувати три процеси:

1. Обробку черги повідомлень.
2. Запис підтверджених подій у `events.jsonl`.
3. Перехід завдання в `done` після успішного бар'єра приймання.

## 2. Завдання J3

### A. Автоматична черга

- Реалізувати безпечний одноразовий запуск обробника `j4 run --once`.
- Передбачити запуск за розкладом без постійно відкритого сеансу J3.
- Забезпечити блокування паралельних обробників.
- Зберегти відновлення після перезапуску.
- Підтримати `J4_HALT` і `bridge/HALT`.
- За замовчуванням використовувати тільки `stub`.

### B. Автоматичний журнал

- Реалізувати запис дозволених подій J4 у `tasks/T-XXXX/events.jsonl`.
- Забезпечити послідовність `seq`, атомарність запису та захист від дублювання.
- Зберігати посилання на докази й контрольний SHA.
- Не дозволяти автоматичне створення записів приймання від імені J3, J5, C3 або JE.
- Не дозволяти автоматичне створення записів рішень JE.

### C. Завершення через ADM

- Реалізувати команду `j4 close --task T-XXXX --subject <SHA>`.
- Використовувати чинний `acceptanceReady` / `requestDone`.
- Відхиляти завершення, якщо бракує перевірок, рецензії або приймання хоча б однієї обов'язкової ролі.
- Перевіряти всі докази на одному контрольному SHA.
- Забезпечити ідемпотентність: повторний запуск не створює другого `done`.
- Заборонити завершення завдань із відкритою ескалацією JE.

## 3. Безпекові обмеження

**Категорично заборонено:**

- Активувати live-режим або платні API.
- Автоматично підтверджувати рішення рівня C.
- Використовувати `--human` як доказ особи JE.
- Змінювати CONTRACT v0.4 без окремого погодження.
- Змінювати CSP, Tauri capabilities, міграції або секрети.
- Зливати PR без рішення JE.
- Використовувати реальні оперативні дані.

Якщо автоматизація вимагає зміни моделі довіри, повноважень JE або автентифікації — зупинитися й передати питання JE.

## 4. Ліміти

- Максимум 20 викликів адаптера J4, **сукупно за всі тестові прогони**.
- Максимум 2 спроби на сценарій.
- Платні виклики: 0.
- Максимальна глибина делегування: 1.
- Рецензент C3: максимум 15 файлів.

Перед кожним прогоном враховувати очікувані виклики. Якщо ліміту недостатньо — зупинитися, не обнуляти лічильник і запросити рішення.

## 5. Критерії приймання

- Черга обробляється автоматично в `stub` без ручного запуску кожного повідомлення.
- Події записуються без дублікатів і втрати послідовності.
- Після перезапуску процес відновлюється коректно.
- Рішення рівня C залишаються заблокованими.
- `done` неможливий без повного комплекту приймань.
- Повторне завершення не змінює стан.
- Усі обов'язкові тести успішні.
- C3 незалежно перевіряє контрольний SHA.
- J3 надає технічне приймання, J5 — змістове.

## 6. Звітність

J3 має надати:

- базовий SHA та контрольний SHA;
- перелік змінених файлів;
- результати тестів і C3;
- фактичний облік викликів;
- підтвердження відсутності платних викликів;
- перелік залишкових ручних операцій;
- PR без злиття.

**Не встановлювати `done` і не зливати PR до завершення передбаченого приймання та окремого рішення JE.**
