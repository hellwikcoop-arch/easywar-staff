## Процедура (кожен раз перед рішенням про закриття T-XXXX)

0. **Стоп-умови.** `bridge/HALT` або `J4_HALT` є; планувальник увімкнено без рішення JE; таблиця вище не заповнена → не продовжувати, доповісти JE.
1. **Змінні.** Вивести `J4_HOME` і `J4_LEDGER` у тому середовищі, з якого запускатимуться команди. Вони мають збігатися з таблицею побайтно (абсолютні шляхи, без симлінків-підмін).
2. **Цілісність журналу.** `J4_LEDGER=… node bridge/bin/j4.mjs verify` → `ok: true`, `problems: []`. Інакше СТОП.
3. **Звірка.**
   ```
   node tasks/T-0009/tools/reconcile-close.mjs --task T-XXXX \
     --home "$J4_HOME" --ledger "$J4_LEDGER" --events tasks/T-XXXX/events.jsonl \
     --expect-first <ledger_first_hash> --expect-head-seq <ledger_head_seq> --expect-head-hash <ledger_head_hash>
   ```
   Код виходу 0 — розбіжностей немає; 3 — СТОП (причини в `stop[]`). Інструмент лише читає: нічого не пише й не синхронізує.
4. **Якщо СТОП.** Нічого не виправляти й не синхронізувати. Звіт JE: вивід інструмента, `stop[]`, `facts.unsynced_open`. Типові причини: `ledger-identity-mismatch`/`ledger-head-mismatch` — не та установка або журнал замінено чи обрізано; `open-escalation` — є відкрита ескалація JE (закривати не можна); `journal-escalation-unknown-to-ledger` — журнал завдання знає ескалацію, якої немає в наданому журналі J4 (хибна пара); `store-ledger-mismatch` — сховище й журнал з різних установок. `facts.unsynced_open` — ескалації, які є в J4, але не дійшли до `events.jsonl`: синхронізація лише за окремим дозволом JE.
5. **Якщо код 0.** Вивід інструмента (JSON) вкласти у звіт для JE разом із поточними `head_seq`/`head_hash`. Це лише умова для того, щоб JE розглядав закриття; сам `done` — окреме рішення JE (D-7).
